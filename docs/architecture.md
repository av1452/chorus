# Code architecture

## Layout

```
src/chorus/
├── devicedb.py          Hardware tables: models, architectures, flash chips
├── errors.py            Exception hierarchy
├── cli.py               Command-line interface
├── usb/
│   ├── protocol.py      Wire format: constants, packet builders, parsing
│   ├── transport.py     Byte pipes: pyusb, hidapi, and a simulated remote
│   └── remote.py        Operations: identify, read/write/erase flash, learn IR
├── ir/
│   ├── signal.py        IRSignal — the type everything converts through
│   ├── protocols.py     NEC, RC-5, SIRC, Panasonic, Samsung, JVC codecs
│   ├── pronto.py        Pronto hex (CCF) conversion
│   ├── lirc.py          lircd.conf import
│   ├── flipper.py       Flipper Zero .ir import and export
│   └── database.py      On-disk code library
├── config/
│   ├── model.py         Devices, activities, buttons, macros; validation
│   └── binary.py        Config blob's internal container (header, sections)
├── hub/
│   ├── discovery.py     SSDP
│   ├── websocket.py     Minimal RFC 6455 client (stdlib only)
│   └── client.py        Hub local API
└── server/
    ├── app.py           HTTP API (stdlib http.server)
    └── static/          Single-page editor
```

## Design decisions

### IRSignal is the hub of the IR code

Every format — Pronto, LIRC, Flipper, a learned capture, a synthesised
protocol frame — converts to and from `IRSignal`. That gives *n* converters
rather than *n²*, and means a code learned from a remote can be exported as
Pronto, or a Flipper record can be decoded as NEC, with no special cases.

### Transport is an interface, with a simulated implementation

`Transport` is an abstract byte pipe. `PyUsbTransport` and `HidApiTransport`
talk to real hardware; `FakeTransport` implements enough of the protocol to
answer identity queries and maintain a sparse byte map of simulated flash.

That is what makes the test suite meaningful without hardware: full
erase/write/read/verify cycles run against the simulator, and tests can
assert on the exact bytes that went out on the wire. `FakeTransport` is also
what `--backend fake` uses, so the CLI can be exercised end to end.

### Hardware tables are generated, not transcribed

`devicedb.py` is generated by `tools/gen_devicedb.py`, which parses
libconcord's `remote_info.h` directly. 120 models, 18 architectures, 7 flash
chips and 6 sector maps is far too much to hand-copy reliably, and
regenerating is how upstream changes get picked up.

### Protocol knowledge lives in one place

`usb/protocol.py` holds every constant and every packet builder, and nothing
else. `usb/remote.py` sequences them but never constructs bytes itself. So
the wire format is testable in isolation — and most of the test suite's
protocol assertions are against `protocol.py` directly.

### No dependencies beyond pyusb

The web UI runs on `http.server`. The WebSocket client is implemented from
scratch against RFC 6455. YAML and hidapi are optional extras. A tool for
rescuing abandoned hardware should not itself rot from dependency churn, and
`pip install chorus` pulling in one package makes it far more likely to
still install in five years.

### Validation warns, it does not refuse

`RemoteConfig.validate()` returns a list of strings rather than raising. A
half-built configuration is a normal intermediate state and must stay
saveable. `--strict` turns warnings into a non-zero exit for CI.

## Error handling

All exceptions descend from `ChorusError`, and the CLI catches that one
type and prints the message without a traceback. So error messages are part
of the interface, and they are expected to say what to *do*:

```python
raise TransportError(
    f"Could not claim the remote's USB interface: {exc}\n"
    "Another program may be holding it (close MyHarmony or "
    "Harmony software if installed). On Linux you may need the "
    "udev rule from packaging/ or to run as root."
)
```

A message that only says what failed has shifted the diagnostic work onto
someone with less context than the code had.

## Testing

```bash
pytest                      # 293 tests, no hardware needed
pytest --cov=chorus
ruff check src tests
```

What is covered:

- **Wire format** — exact bytes of every command, both length-code tables,
  the chunk caps, sequence validation including the documented Harmony 880
  firmware glitch.
- **Hardware tables** — every model index resolves; known skin IDs map to the
  right models; architecture fields match libconcord; flash lookup handles
  swapped IDs.
- **IR codecs** — more than 20,000 encode/decode round-trips across the
  protocols' full parameter ranges, including RC-5 exhaustively. Plus
  cross-protocol non-collision, and tolerance of injected jitter.
- **Pronto** — round-trips, header validation, malformed input, the
  unconvertible `5000`-series.
- **Importers** — LIRC `SPACE_ENC` and `raw_codes`, Flipper parsed and raw
  records, directory-tree import with per-file error collection.
- **Configuration** — round-trips through dict and disk, and every validation
  warning.
- **Flash operations** — full erase/write/read/verify against the simulator,
  parameterised across every write-block size and the chunk boundary.
- **Binary container** — header parsing, section table, every corruption
  path, against synthetic blobs built to the documented shape for every
  known architecture signature.
- **WebSocket** — handshake, masking, fragment reassembly, extended lengths,
  automatic pong, close, and refusal handling, all against a scripted server.
- **CLI** — every subcommand's exit code and error text.

What the automated suite does not cover: writing to real hardware (still
unproven, see the README). Reading has been exercised against a real
Harmony 665 — identity, backup, and the binary container parser all ran
successfully against actual flash contents during development, independent
of the unit tests above.
